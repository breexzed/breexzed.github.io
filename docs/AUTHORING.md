# Authoring The Estate

This is the practical guide for living inside the estate: how to publish, how to update, and where to place text, images, links, and code.

## 1. Where content lives

- All public estate content lives in `nodes/`.
- Each markdown file in `nodes/` becomes one node in the estate.
- The route for that node becomes `/node/:id`.
- The main public surfaces (`/`, `/corpus`, `/signals`, `/projects`) are discovery layers.
- The dedicated reading surface is always the node page at `/node/:id`.

## 2. Which template to start from

Copy one file from `templates/` and rename it into the right folder under `nodes/`.

- `templates/concept.md`
- `templates/articulation.md`
- `templates/signal.md`
- `templates/trail.md`
- `templates/projects.md`

The seeded content is only there as current demo content. You can delete or replace it node by node when you are ready.

## 3. The minimum publishing workflow

1. Copy the right template into `nodes/<type>/your-file.md`.
2. Fill in the frontmatter.
3. Write the body in normal markdown.
4. Run `npm run build:content`.
5. Run `npm run smoke` when you want the quick browser verification too.

If the build passes, the estate has accepted the node.

## 4. What frontmatter does

Core fields:

```yaml
id: your_stable_node_id
title: Human Title
formula: relation -> meaning
depth: 1
type: concept
status: published
parent: root
children: []
connects: []
```

Important rules:

- `id` must be lowercase and stable.
- `children` is for structural movement through the estate.
- `connects` is for cross-links and graph relations.
- `source` is authored provenance.
- `sourcePath` is generated by the compiler. Do not author it manually.

### Folders and collections

Use `folder: true` when a concept, project, or articulation needs its own browsable container. Keep the node's normal category in `type`; the folder flag adds containment without creating a new taxonomy:

```yaml
id: worlds
title: Worlds
label: concept
formula: worlds -> relations -> systems
depth: 1
type: concept
folder: true
parent: root
children:
  - being_in_the_world
  - systems_as_world
connects:
  - world_as_systems
```

Place the folder and its notes together under a directory such as `nodes/worlds/`. The folder page lists its `children` as notes in the folder, while `connects` remains available for cross-links outside the folder.

When deployed to Vercel or another host with the included fallback rewrite, copied node links use clean paths such as `/node/<id>` and remain valid when pasted into a new tab or opened on mobile. GitHub Pages keeps the safe `/#/node/<id>` hash fallback because it does not provide server rewrites. Folder cards use one readable `FOLDER` badge as their visual marker; no extra icon or special app wiring is required.

### Quick folder setup

The easiest workflow is:

```bash
mkdir -p nodes/my-folder
cp templates/folder.md nodes/my-folder/my-folder.md
```

Then edit the copied file:

```yaml
id: my_folder
title: My Folder
type: concept
folder: true
parent: root
depth: 1
children:
  - first_note
```

For each note inside it, use `parent: my_folder`, set `depth: 2`, and add the note ID to `children`. Keep `children` for containment and `connects` for meaningful relationships that should remain visible in the graph. A folder's `type` determines whether it appears with Concepts, Projects, or Articulations; its `folder: true` flag adds the readable folder marker. A folder's `thumbnail` is used on global cards; its `visual` is used on the folder detail page. Child cards inside the folder use each child's own thumbnail, description, formula, and links.

After authoring:

```bash
npm run build:content
npm run dev
```

If the build reports a missing child or duplicate ID, fix the frontmatter and run the same command again. The app wiring is already generic; normal folder creation should only touch `nodes/`, `templates/folder.md`, and the folder's visual assets.

## 5. How internal links work

Link to another node by linking to its markdown file.

Example:

```md
[Knowledge In Motion](../articulations/knowledge-in-motion.md)
```

The runtime resolves that to the canonical node page automatically.

That means:

- internal markdown links stay inside the estate
- internal markdown links also appear as compact previews with the linked node's thumbnail, category, formula, and description
- graph clicks stay inside the estate
- corpus cards stay inside the estate
- search results stay inside the estate

Use normal external URLs when you want a plain outbound link; only relative or root-relative links to `.md` files become node previews.

Absolute `http://` and `https://` links in node body content are rendered as live-link preview cards. They show the linked label, host, and path, open in a new tab, and remain ordinary external links underneath. This keeps previews reliable without embedding third-party pages that may block frames or expose visitors to unnecessary tracking.

The preview intentionally does not fetch or embed the external page's contents. Browsers generally block cross-origin content reads through CORS, and many sites block iframes with security headers. If an external source needs a richer preview, add a short authored quotation or summary below the live link in the node body instead. That keeps the estate readable, attribution clear, and the external page in control of its own content.

Example:

```md
Further reading: [Shape Up — Foreword](https://basecamp.com/shapeup/0.1-foreword)

> A short excerpt or your own summary of why this source matters here.
```

## 6. How to add images

You have two good options.

### Inline image in the body

Put the image near the node file and reference it relatively in markdown.

```md
![Field sketch](./image-name.jpg)
```

During `npm run build:content`, the asset pipeline copies supported images into public assets and rewrites the path.

### Hero/supporting image from frontmatter

Use:

```yaml
visual: ./image-name.jpg
```

or

```yaml
thumbnail: ./image-name.jpg
```

The dedicated node page will render that image as a large visual block.

Supported asset extensions:

- `.png`
- `.jpg`
- `.jpeg`
- `.gif`
- `.svg`
- `.webp`
- `.avif`

## 7. How to add code snippets

Use fenced markdown code blocks.

```md
```ts
export function helloEstate() {
  return 'hello';
}
```
```

The node page renders code blocks in a dedicated code shell, and project nodes use the same markdown rendering.

Use language tags when you can:

- `ts`
- `js`
- `tsx`
- `bash`
- `json`
- `md`

## 8. How to add external links

Use normal markdown links.

```md
[Reference](https://example.com)
```

Use external links only when the thing genuinely lives outside the estate.

If the resource should remain part of the estate, make it another node and link the markdown file instead.

## 9. How each node type should feel

`concept`

- durable lens
- framing idea
- organizing thought

`articulation`

- shaped expression
- public statement
- synthesis or claim

`signal`

- something encountered in the world
- still live, still moving
- something being tracked

`trail`

- the trace of contact
- note, margin, fragment, confirming evidence

`projects`

- builds, experiments, products, implementations
- can include images, code, links, and external references

## 10. What catches edge cases 

The compiler already catches:

- duplicate IDs
- missing required fields
- invalid node types
- invalid signal status values
- broken `parent` references
- broken `children` references
- broken `connects` references
- broken internal markdown links

The smoke layer checks:

- `/map` not-found behavior
- `/node/:id` dedicated node page
- search-to-node routing
- internal markdown link routing

## 11. Social and account config

Edit:

- `src/config/site.ts`

That file controls:

- GitHub
- Mail
- X
- Spotify
- YouTube when you are ready

If a value is empty or `null`, it will not render in the footer.

## 12. The mental model

Think of the estate like this:

- `nodes/` is where you write reality into the system
- the build pipeline turns it into a coherent public topology
- discovery surfaces help people arrive
- node pages are where they actually stay and read
- the map is for relation
- the node page is for encounter
